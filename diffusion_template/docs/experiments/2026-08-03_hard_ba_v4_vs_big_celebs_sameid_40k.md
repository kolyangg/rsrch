## Top differences in the new version

The rows below describe intended mechanisms, not claimed training results. V4
had passed construction, routing, gradient, and ownership checks when this
document was written, but its quality/identity trajectory still had to be
measured over the planned training run.

| Priority | Top v4 difference | Problem in the historical run | Why it was added | What it tries to achieve | Decisive evidence during the run |
|---:|---|---|---|---|---|
| 1 | **Exact BA-only ownership: 12.329M parameters instead of 171.295M live trainables** | A swallowed installation exception prevented the intended freeze pass. The old optimizer therefore contained the intended 31.949M BA parameters plus 46.449M generic U-Net LoRA parameters and 92.897M pretrained PhotoMaker-adapter parameters. Identity improved, but the improvement cannot be assigned specifically to BA. | The scientific question is whether explicit target-query/reference-KV attention learns identity. That question is unanswerable if ordinary SA, ordinary CA, and the PhotoMaker adapter are simultaneously adapting. V4 processors declare their own allowed parameters, and startup compares the complete requires-grad and optimizer sets against that declaration. | Make any change in identity, prompt adherence, or structure attributable to the explicit BA route rather than hidden broad fine-tuning. It also reduces memory, optimizer state, and checkpoint ambiguity. | Startup must remain exactly 368 tensors / 12,328,960 parameters with roles `ref_query`, `ref_kv`, and `ref_output`; there must be zero generic, PhotoMaker-default, CA, mix, or gate trainables. |
| 2 | **Hard reference replacement is retained, with no native/reference face mixer** | Later anchored-mix experiments learned to reduce their reference coefficient and returned toward the native PhotoMaker face path. This made good-looking but increasingly PhotoMaker-like images an easier optimization solution than strong reference use. The old same-ID run did not have this mixer and showed a clearer multi-thousand-step identity rise. | The historical run's strongest useful architectural clue was not its broad trainable set; it was that reference self-attention was forced to own the target-face message. V4 reconstructs that rule directly and removes every alpha, gate, floor, schedule, RMS match, and override that could attenuate it. | Force the model either to improve the explicit reference-conditioned BA representation or expose that the representation is insufficient. The model cannot conceal failure by gradually routing the face back through native attention. | `ba/hard_face_native_leakage` must stay exactly zero. Identity should recover across later gates while reference-sensitive diagnostics remain active. If identity fails, it is a real hard-route failure rather than mixer retreat. |
| 3 | **A branch-only trainable target query is added, rank 16** | A pure frozen target query can be a bottleneck: the query basis inherited from PhotoMaker was not trained specifically to retrieve spatial identity features from explicit reference K/V. Conversely, the old `noise_and_ref` model trained target Q/K/V globally, so it had useful target-side adaptability but also changed native/background attention. | Query adaptation is the smallest targeted way to recover the useful target-side capacity suggested by the historical run. V4 clones the effective target-Q projection at initialization, then trains only the copy used by the reference branch. | Learn *where and how* target face locations should retrieve identity information from the reference, without changing native target attention outside the face. At initialization the branch query is identical to the frozen query, so the change begins as a capacity addition rather than a random route. | `ba/branch_query_delta_rms_ratio` should grow from approximately zero without instability. A growing query delta should coincide with improved correct-reference identity, not merely loss reduction. |
| 4 | **Native target Q/K/V are frozen and used only outside the face** | In the old `noise_and_ref` processor, target/noise Q/K/V were trainable throughout the patched sites. The model could improve the objective by changing generic target self-attention and background/structure behavior, not solely reference retrieval. | Native attention is already structurally strong. Freezing it provides a stable composition/pose/background anchor while the face-local branch learns identity. It also prevents the new target-query capacity from altering regions that do not require reference identity. | Preserve PhotoMaker/SDXL structure outside the target-face mask while concentrating adaptation inside the explicit BA route. This should reduce global drift, prompt deterioration, and accidental target-image memorization. | Outside-mask outputs must equal the frozen native path in the processor check. During validation, text, composition, and non-face structure should remain stable as identity changes. |
| 5 | **Dedicated rank-32 reference-output residual** | The old branch reused ordinary `attn.to_out`, while accidentally trainable generic and PhotoMaker adapters also modified that shared output basis. Reference K/V therefore did not have a clean, independently owned way to translate retrieved reference features into the target residual stream. | Query and K/V rank alone do not guarantee that retrieved features are expressed in the right feature basis. A branch-specific output residual gives the reference route its own final transformation without changing the native output projection. It is zero initialized so the added residual starts neutral. | Let the branch learn how to express identity detail after attention, while preserving the pretrained output basis and avoiding ordinary SA/CA drift. This separates retrieval capacity (`ref_query`, `ref_kv`) from expression capacity (`ref_output`). | The `ref_output` group should receive finite gradients and learn at `1e-4`. Reference/native RMS and cosine should change in a controlled way rather than exploding or collapsing. |
| 6 | **Only 46 mid/up self-attention sites are patched instead of all 70 sites** | The historical configuration trained all eligible SA sites, including low-resolution/down-path sites, and combined that with broad adapters. This was expensive and allowed identity training to alter global layout and early feature extraction. Previous diagnostics indicated that mid and early up blocks are the most relevant face-synthesis locations. | V4 focuses capacity on `mid_block`, `up_blocks.0`, and `up_blocks.1`, where spatial face structure and visible detail are synthesized. Down blocks and the final high-resolution up group retain their pretrained behavior. | Improve identity with less global structural interference, fewer parameters, lower optimizer cost, and clearer layerwise attribution. | Layer-group telemetry should show useful activity in `mid`, `up0`, and `up1`. If one group stays inactive or causes artifacts, a later controlled ablation can change site selection without changing the core route. |
| 7 | **FP32 trainables over the frozen BF16 backbone** | The old 840 intended BA tensors and their Adam moments were BF16. Small low-rank updates can be quantized or lost at this precision, especially late in training when gradients become small near a plateau. | Keeping only the small adapter set in FP32 is affordable and removes precision as a plausible cause of early saturation. The large frozen SDXL/PhotoMaker backbone remains BF16. | Preserve small query/K/V/output updates and optimizer statistics over long training, improving numerical stability and late-stage learning capacity. | No non-finite gradients or optimizer states; trainable manifests report FP32; useful route/query changes can continue beyond the early training phase. |
| 8 | **Training timesteps are restricted to inference-active BA support** | The old run sampled uniformly over all training timesteps while inference enabled BA only from step 15 of 50. Roughly 30% of the denoising-progress range could therefore train BA in conditions where it would not be used at inference. | Capacity should be spent on the exact noise levels where the branch contributes during generation. The new policy derives the eligible support from the fixed inference process rather than treating every diffusion timestep as equally relevant. | Reduce train/inference mismatch and make each optimizer update more relevant to actual generated images. It also makes denoising-progress telemetry meaningful. | `ba/denoise_progress_mean` and sampled supports must remain inside the configured active range. Improvements should appear in generation rather than only in training loss. |
| 9 | **The loss now combines full-image, face, and boundary-ring terms** | The historical run used face-crop epsilon MSE on every update. It did not directly preserve the full image or penalize seams and feature discontinuities at the hard mask boundary. Identity could improve while text/composition drifted or face integration became strained. | Hard replacement creates an especially important boundary between reference-conditioned face features and native surrounding features. The new `1.0 full + 1.0 face + 0.1 boundary` loss protects global denoising while still emphasizing the face and its transition ring. | Improve identity without sacrificing pose, prompt adherence, anatomy, hair/skin transitions, or face/body integration. | Track `loss_full`, `loss_face`, and `loss_boundary` separately. Visual review must check eyes, jaw, hairline, neck, and face boundary—not just aggregate identity. |
| 10 | **Detached wrong-reference diagnostics are added, but no rank loss is optimized** | The old run had no counterfactual measurement showing whether correct reference content mattered. Later rank-loss experiments could show reference sensitivity, but sensitivity did not necessarily align with useful identity and could complicate the first architecture test. | V4 spatially shuffles the reference on 25% of sampled diagnostics and measures the prediction/error difference, but detaches this branch and assigns it zero objective weight. This provides causal evidence without steering optimization. | Separate three cases: the branch is ignored; the branch is active but uses only generic reference statistics; or the branch specifically benefits from correct spatial reference information. | Correct-reference versus shuffled-reference gaps and prediction deltas should be nonzero and preferably strengthen with identity. Because the diagnostic is detached, it cannot itself explain a quality change. |
| 11 | **Pinned policy-v1 target/reference scheduling replaces stochastic sampling** | The old run's exact target, reference, and augmentation sequence was not recoverable. Reference quality varied randomly, and repeated or difficult pairs could differ between runs. This weakens architecture comparisons and resume fidelity. | The scheduled loader pins every target/reference/flip row, rejects self/cross-ID pairs, uses canonical high-resolution references, and has an explicit aligned resume offset. | Reduce data-order noise, guarantee broad target coverage, and make reruns and checkpoint continuations exact. The intent is to give the architectural experiment a stable training signal. | Schedule hash, row offset, zero leakage, and target/reference counts must pass preflight. This remains a comparison confound versus the historical run, so absolute improvement cannot be called a one-variable architecture result. |
| 12 | **Validation uses `validation_native` rather than `legacy_full_copy`** | The historical run copied the training-side processor/base state into the alternate RealVis validation model. That could carry base-dependent projection behavior into a model on which those projections were not originally constructed, and it made checkpoint interpretation less explicit. | V4 first constructs effective projections from the actual RealVis validation base and then loads only the versioned trainable BA deltas. Training and validation use the same v4 routing/roles while respecting the different frozen base. | Make inference behavior reproducible and prevent hidden training-base processor state from contaminating alternate-base validation. | V4 checkpoints must load with an exact architecture manifest and 46-processor audit. Because this changes step-0 semantics, compare within-run deltas rather than raw historical versus v4 scores. |
| 13 | **Schema-v2 checkpointing saves the complete live trainable state** | The historical checkpoint saved BA processors and the generic adapter but omitted the accidentally live pretrained PhotoMaker/default adapter. The exact model that generated later historical metrics therefore cannot be reconstructed from its checkpoint. | V4 enumerates every allowed trainable name, shape, dtype, role, routing flag, and processor site. Loading fails if the current architecture differs. | Ensure every 2k checkpoint can reproduce its validation path and can be resumed without silently losing learned capacity. | Save/load manifests must match exactly; missing, unexpected, shape-mismatched, or architecture-mismatched tensors must fail closed. |
| 14 | **Role-specific learning rates and gradient clipping** | The historical one-rate optimizer applied `1e-4` to both intended BA tensors and all accidental adapters, with no gradient clipping. Hard routing can produce sharp early gradients, and query/K/V projections need not share the output adapter's optimal step size. | V4 uses `5e-5` for target-query and reference-K/V retrieval, `1e-4` for the zero-initialized output residual, and max gradient norm 1.0. | Let output capacity become useful quickly while adapting attention geometry more conservatively and preventing early instability. | Per-role gradients must remain finite and nonzero. The run should avoid early loss spikes, NaNs, anatomy collapse, or an output-residual explosion. |

### How the main architectural path changed

| Stage | Historical `noise_and_ref` hard route | New query-adaptive hard BA-v4 | Design intent |
|---|---|---|---|
| Target features enter SA | Trainable rank-32 target/noise Q/K/V copies were used across the patched attention path. | Frozen native target Q/K/V define the native path; a separate rank-16 Q clone is used only for the reference branch. | Adapt reference retrieval without rewriting native/background attention. |
| Reference features enter SA | Trainable rank-32 reference Q/K/V copies. | Trainable rank-32 reference K/V only; reference-lane Q and the reference lane itself stay native. | Spend capacity only on tensors consumed by target queries. |
| Target face attention | Trainable target Q attends to trainable reference K/V. | Branch-only target Q attends to true-key-masked reference K/V. | Preserve explicit target-to-reference information flow and make its mask auditable. |
| Target non-face attention | Used the trainable target/noise attention path. | Uses the frozen native target attention path exactly. | Protect prompt, pose, composition, and background. |
| Attention output | Shared native `to_out`, affected by accidentally trainable ordinary adapters. | Frozen native `to_out` plus a branch-owned rank-32 zero-initialized output residual. | Give reference identity a dedicated expression basis without changing native output. |
| Spatial merge | Hard mask; reference face replaces target face-attention output. | Same hard-mask principle, enforced at unit scale with a zero-leakage diagnostic. | Retain the old run's useful reference-dominant inductive bias while removing escape routes. |
| Transformer residual | Standard residual connection remained after the attention processor. | Same standard residual connection remains. | Hard replacement concerns the attention message; it does not delete the U-Net residual stream or PhotoMaker conditioning. |
| PhotoMaker conditioning | Standard PhotoMaker token/cross-attention conditioning remained and its default adapter accidentally trained. | Standard PhotoMaker conditioning remains, but its adapter and ordinary cross-attention projections are frozen. | Preserve PhotoMaker composition/pose priors without allowing them to absorb the new learning objective. |

## Branched-attention architecture

| Item | Historical same-ID run | Current hard BA-v4 run | Significance |
|---|---|---|---|
| Architecture selector | Historical `hard_replace_v1` behavior; `branched_attn_weight_mode=noise_and_ref`. | `query_adaptive_hard_sa_v4`; explicit hard fusion; no mix override. | V4 is a clean reconstruction, not a resume of the old model. |
| Core target-face route | Target queries attend to reference-only K/V inside the target-face mask. | Branch-adapted target queries attend to true-mask-filtered reference K/V inside the target-face mask. | Both preserve the central branched-attention idea. |
| Face merge | `native/background × (1-mask) + reference-face × mask × 1.0`. No native/reference face interpolation. | `native × (1-mask) + reference-face × mask`. Scale is required to equal 1.0. | Both force the reference branch to own the target-face self-attention message. |
| Native face-attention mix or gate | None. | None; v4 has no alpha, mix, gate, floor, schedule, or RMS matching. | PhotoMaker cannot retake the face route through a learned mixer. |
| Target/background path | Trainable target/noise Q, K, and V copies, rank 32. | Frozen native target Q, K, and V outside the face. Only the explicit branch target-Q adapter trains. | The old run could adapt the whole target self-attention path; v4 isolates target-side adaptation to reference retrieval. |
| Branch target query | Rank-32 target/noise Q adapter. | Branch-only target-Q LoRA, rank 16, initialized as an effective clone of target Q. | V4 retains query adaptability at half the old rank and without changing native/background Q. |
| Reference K/V | Rank-32 trainable reference K/V. | Rank-32 FP32 reference K/V LoRA over effective frozen projections. | This is the closest retained capacity from the old architecture. |
| Reference Q | Rank-32 trainable reference Q existed as part of `noise_and_ref`. | No trainable reference-Q role; the reference lane stays native/frozen. | V4 removes capacity that does not directly help target queries retrieve reference identity. |
| Branch output basis | Shared ordinary `attn.to_out`; accidental generic and PhotoMaker output adapters were also trainable. | Frozen native `to_out` plus a dedicated rank-32 zero-initialized reference-output residual. | V4 can learn a reference-specific output correction without altering the native output path. |
| Patched SA scope | Historical `noise_and_ref` installation: 70 SA sites, reconstructed from 840 processor tensors at 12 tensors/site. | 46 selected SA sites: `mid_block`, `up_blocks.0`, and `up_blocks.1`. | V4 concentrates capacity in mid/high-resolution synthesis blocks and reduces cost. |
| Branched cross-attention | Disabled. | Disabled. | Fixed. Standard frozen PhotoMaker token conditioning still remains in both models. |
| `pose_adapt_ratio` | `0.0` | `0.0` | Neither replaces reference-face K/V with target K/V. |
| `ca_mixing_for_face` | `false` | `false` | Neither hides the SA mechanism with face-local CA mixing. |
| BA timestep support during training | `uniform_all`; BA trained at uniformly sampled diffusion timesteps, including regions where inference would not activate it. | `inference_active`; samples the support at which BA is active in the fixed 50-step inference process. | V4 better aligns training with inference-time route usage. |
| Reference-key masking | Historical reference mask path, without a strict installation/routing contract. | Explicit true reference-key bias; zero valid reference keys fail closed. | V4 makes the spatial reference route auditable. |

## Evidence and interpretation

| Question | Historical evidence | What v4 must show |
|---|---|---|
| Did identity improve over several thousand steps? | Yes within the historical run: identity was `0.3063` at step 0, dipped to `0.2841` at 2k, reached `0.3723` at 10k, and peaked at `0.3817` at 18k. | Do not judge at 2k alone. Look for sustained recovery by 8k and a meaningful gain by 12k–20k relative to v4's own step 0. |
| Did the old run establish that BA caused the gain? | No. The hard BA route was active, but approximately 139.35M unintended generic/PhotoMaker adapter parameters also trained. | Exact ownership plus route telemetry must make the improvement attributable to the explicit target-Q/reference-KV path. |
| Did the old run preserve prompt behavior? | Not fully: text similarity declined from `27.8118` at 2k to `26.5120` at 20k. | Identity improvement should not be purchased through a similar sustained text or structural-quality regression. |
| Is v4 an exact controlled replay? | No. | Dataset scheduling, SA site selection, dtype, loss, gradient clipping, timestep support, output adapter, validation processor construction, and total budget differ. Treat it as a clean architectural successor, not a one-variable ablation. |
| What would count as success? | The old trajectory supplies a qualitative target: an early dip followed by multi-gate identity growth through roughly 10k–18k. | Hard leakage remains zero; correct-reference diagnostics remain stronger than shuffled controls; identity rises materially from v4 step 0; face quality, anatomy, text, and boundary integration remain stable. |
| What would count as failure? | The old run cannot answer this cleanly because of broad trainables. | Identity stays near/below initialization through 12k–20k despite nonzero route/query telemetry, or identity gains require worsening anatomy, face quality, or prompt adherence. That would implicate the hard BA representation/objective rather than a mixer escape route. |

## Bottom line

| Conclusion | Comparison |
|---|---|
| What is deliberately the same | Sealed BigCelebs source, batch size 2, hard reference replacement inside the face, target-query/reference-KV BA, no face mix/gate, BA cross-attention off, `pose_adapt_ratio=0`, `ca_mixing_for_face=false`, SDXL/PhotoMaker training base, RealVis full-96 validation target, and 2k validation cadence. |
| What is deliberately changed | V4 isolates trainable target-query retrieval, reference K/V, and reference output capacity; freezes native/background and PhotoMaker paths; uses FP32 exact ownership and complete checkpoints; aligns BA timesteps with inference; adds structure/boundary loss and causal diagnostics; and removes every accidental broad adapter. |
| Correct interpretation | The historical run proves that this hard-routing family can move identity over a 10k–18k horizon, but not that BA alone caused the gain. V4 tests whether the same core BA idea works when the mechanism is explicit, attributable, and recoverable. |
